# Certificate lane for the three order-16 cross-degree cases

Status on 2026-08-01: **all three proof-producing order-16 runs completed**.
CaDiCaL returned UNSAT for `d=1,2,3`; `drat-trim` verified every emitted DRAT
and converted it to LRAT; the separate `lrat-check` executable accepted every
LRAT.  Compressed LRATs and a clean replay script are retained under
`cross_certificates/`.

This lane starts from the exhaustive `d=1,2,3` reduction and independent
native-cardinality UNSAT results in `Z3_CROSS_SEARCH.md`.  It removes the main
remaining finite-search trust gap by translating the MiniCard formula to
ordinary DIMACS and providing distinct solver, DRAT-check, and LRAT-check
stages.  The verified certificates close the finite order-16 search only
conditional on the McKay catalogue-completeness premise and reduction
documented there; they do not solve Erdős problem 128 at all orders.

## What is encoded

`cross_proof_cnf.py` uses edge variables 1 through 120 and adds the same source
constraints as `minicard_cross_search.py`:

1. triangle-freeness;
2. a fixed independent six-set and `alpha <= 6`;
3. at least six edges in every eight-set;
4. existential common-neighbour witnesses making the graph maximal
   triangle-free;
5. the fixed prefix neighbourhood for the minimum-cross-degree vertex and
   cross degree at least `d` for every outside vertex; and
6. the redundant averaged consequence `e(G) >= 26`.

The three native cardinality families are replaced by PySAT 1.9.dev7
sequential counters sharing one `IDPool`.  No Z3 neighbourhood-ordering
symmetry is used.  The generator asserts the exact source-family counts, that
the 120 edges are the DIMACS prefix, that `CNF.nv == IDPool.top`, and that the
literal support is exactly the gap-free interval `1..nv`.

This gives three logically separate claims:

- **CNF equivalence:** existentially quantifying counter and witness variables
  gives the source graph constraints.  This is supported by the semantic
  audit below, but is not an UNSAT result.
- **Solver result:** CaDiCaL exit 20 is only an UNSAT claim until its emitted
  DRAT is checked.
- **Certificate verification:** `drat-trim` must report `s VERIFIED`, emit
  LRAT, and the separate `lrat-check` invocation must report `c VERIFIED`.
  The two checkers share one upstream repository and are not formally verified;
  a theorem-level release should additionally use a formally verified LRAT/LPR
  checker on a separate machine.

## Retained semantic audit

`audit_cross_proof_encoding.py` exercises the exact helpers imported by the
generator.  Its current run reports `PASS` after:

- 4,096 assignment checks: every assignment for every at-least bound on widths
  one through eight;
- all 64 assignments at each target cross bound `d=1,2,3`;
- 1,112 deterministic assignments for the 28-input, bound-six half counter;
- 1,387 deterministic assignments for the 120-input, bound-26 global counter;
  and
- all 1,098 graphs through order five for the maximality-witness encoding.

For every cardinality assignment, the CNF plus fixed input assumptions is
satisfiable exactly when the native sum meets the bound.  For every small
graph, the witness CNF is satisfiable exactly when every missing edge has a
common neighbour.

Run it directly with:

```powershell
python experiments/erdos128/audit_cross_proof_encoding.py
```

## Disk-safe proof gate

The proof path rechecks the pinned CaDiCaL/drat-trim source commits, source
cleanliness, build manifest, and exact executable hashes already documented in
`PROOF_PIPELINE.md`.  It also refuses to run while the PID in
`.tmp/erdos128_n16_maple.pid` is active.

Proof sizes are not predictable from the 65 MB inputs.  Consequently, the
wrapper uses a hard WSL `ulimit -f` for every named solver/checker output and a
free-space inequality rather than treating an input-size multiplier as an
estimate.  At completion, five capped files can coexist: DRAT, LRAT, and three
logs.  Before launching the solver it therefore requires

```text
free bytes after DIMACS >= 5 * MaximumArtifactBytes + ReserveFreeBytes.
```

With the defaults of 8 GB per named artifact and a 10 GB reserve, this is a
50 GB launch floor.  An earlier attempt was deferred when drive C had exactly
12,567,814,144 free bytes and direct solver PID 76528 was active.  When free
space later rose above 167 GB, that uncertified direct run was stopped and the
three capped proof cases were launched.  All completed within their caps.

The command used per cross-degree was:

```powershell
powershell -ExecutionPolicy Bypass -File `
  experiments/erdos128/cross_proof_pipeline.ps1 -RunProof `
  -AcknowledgeLargeRun -CrossDegree D `
  -OutputDirectory .tmp/erdos128-cross-proof-dD
```

The hard cap can cause a difficult run to terminate without a certificate; it
cannot convert a capped or interrupted run into evidence of UNSAT.
