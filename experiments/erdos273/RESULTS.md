# Erdős problem 273: finite search results

Date: 2026-08-01

## Status

No covering system for the `p >= 5` target was found.  The open problem is
**not solved** here.  The results below are rigorous finite obstructions,
reproducible exact-search results, and explicitly labelled heuristic failures.

## Lean statement audit

`FormalConjectures/ErdosProblems/273.lean` at commit
`735aee074327b8e78b0d92bb1ee8ea00937c3f51` asks

```text
answer(sorry) <-> exists c : StrictCoveringSystem Z, ...
```

where every modulus is the ideal generated by `p - 1` for a prime `p >= 5`.
`StrictCoveringSystem` has a finite index type, requires the union of the
chosen cosets to be all of `Z`, rules out zero and unit ideals, and requires
the moduli map to be injective.  Thus it encodes a finite covering by one
class for each of a set of distinct positive moduli `p - 1`.  The target is
the positive/existence direction: an explicit certificate would establish
that the answer is `True`.  No defect in the formalization was found.

## Finite formulation

For a common period `L`, the complete set of potentially usable moduli is

```text
S(L) = { d : d | L, d >= 4, and d + 1 is prime }.
```

For each `d` one either chooses no class or one residue `r_d (mod d)`.  It is
enough to cover every integer in `[0,L)`.  All admissible moduli are even, so
each chosen class lies wholly in one parity.  Dividing that parity by two
turns a modulus `d` into a modulus `d/2`; consequently the original problem
is also equivalent to finding two disjoint collections of the half-moduli,
each of which covers all integers.

## Exact density sieve

A necessary condition is

```text
D(L) := sum_{d in S(L)} 1/d >= 1.
```

Since every `d` divides `L`, this was checked with exact integers by testing
`sum L/d >= L`, not floating point.  `density_sieve.py` checked every
`1 <= L <= 1,000,000`.

* No `L < 55,440` passes the density test.
* The first feasible period is `L = 55,440`, with
  `D(L) = 57,861 / 55,440 = 6,429 / 6,160`.
* The best period below it is `L = 50,400`, whose available classes have
  total mass only `49,892`, a deficit of `508` residues per period.
* There are 90 density-feasible periods at most `1,000,000`.

The exact output is in `density_sieve_1e6.log`.

## Parity-triangle obstruction

Let `epsilon = D(L) - 1`.  Any actual subcollection has total density at
most `D(L)`, so its total multiplicity beyond the union has density at most
`epsilon`.  If `1/d > epsilon`, modulus `d` is mandatory: omitting it leaves
total available density below one.

Suppose `60 | L` and `epsilon < 1/30`.  Then the moduli `4`, `6`, and `10`
are all mandatory.  If two of their selected classes have the same parity,
they intersect because every pair has gcd two.  Their possible intersection
densities are

```text
1/lcm(4,6) = 1/12,
1/lcm(4,10) = 1/20,
1/lcm(6,10) = 1/30.
```

Each exceeds the entire overlap budget `epsilon`, so the three classes would
have to be pairwise disjoint.  That would require three distinct parities,
which is impossible.  Therefore no such `L` can be the LCM of a solution.

This elementary criterion eliminates 63 of the 90 density-feasible periods
at most `1,000,000`:

In particular:

* `L = 65,520` has `epsilon = 713/65,520 < 1/30`, so it is impossible.
* `L = 100,800` has `D(L) = 11,201/11,200` and

## The first unresolved period: 55,440

The 43 admissible moduli are recorded in `sat_55440.log` and
`cdcl_55440.log`.  Its excess is `2,421/55,440 = 269/6,160`, so the simple
parity triangle does not apply.  Density forces moduli

```text
4, 6, 10, 12, 16, 18, 22
```

to be present.  More generally, if two chosen classes intersect with density
greater than `269/6,160`, that pair is impossible.  Normalizing the modulus-4
residue to zero forces the modulus-6 and modulus-10 residues to be odd and
gives further incompatibilities involving moduli 12, 16, and 18.

Neither exact solver finished this instance within the attempted caps:

* Z3 built the 55,440 coverage constraints in 97.262 seconds, then remained
  unresolved until the bounded outer process ended.
* CaDiCaL used 212,597 variables and 374,229 clauses before structural cuts;
  both the baseline and strengthened five-minute attempts ended without a
  SAT/UNSAT result.

Therefore `L = 55,440` remains **unknown**, not UNSAT.

## Selfridge `p >= 3` regression fixture

`selfridge_360.json` is a solver-produced period-360 system using all twelve
admissible moduli

```text
2,4,6,10,12,18,30,36,40,60,72,180.
```

It was exhaustively rechecked by `check_certificate.py --allow-two`.  The
modulus 2 class covers one parity and all other selected residues cover the
other parity.  This verifies the known `p >= 3` variant and the search code,
but it is not a certificate for the target because modulus 2 corresponds to
the forbidden prime 3.

## Heuristic searches (not obstructions)

Randomized coordinate descent found no witness:

* `L = 55,440`: best assignment left 7,804 of 55,440 residues uncovered in
  60 seconds (`heuristic_55440.log`).
* `L = 332,640`: best assignment left 38,056 of 332,640 residues uncovered in
  120 seconds (`heuristic_332640.log`).

These failures have no rigorous negative meaning.

## Reproduction

All files in this directory are independent of the Formal Conjectures source
tree.

```powershell
python density_sieve.py 1000000 --hits 50
python cdcl_cover.py 100800 --timeout 300
python cdcl_cover.py 360 --allow-two --certificate selfridge_360.json
python check_certificate.py selfridge_360.json --allow-two
```

`z3-solver` and `python-sat` were installed in the user Python environment.
